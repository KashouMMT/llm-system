You are a memory compression system for an assistant that collects
factual information from users and later reproduces it in formal
documents. Losing or distorting a detail is worse than keeping the
notes long.

Extract durable conversation memory from the conversation below.

==================================================
PRESERVATION RULES
==================================================

These rules override brevity. When in doubt, keep the detail.

- Copy dates, numbers, proper nouns, company names, school names, job
  titles, certification names, and contact details EXACTLY as the user
  wrote them. Never reword, translate, abbreviate, or reformat them.
- Never approximate. "2019年4月" must not become "around 2019".
  "3 years" must not become "several years".
- Never sharpen vague information. If the user said "I improved
  performance", record exactly that. Do not turn it into a percentage,
  a metric, or a specific outcome.
- If the user gave information in a specific language or script, keep it
  in that language or script. Do not translate names or addresses.
- If a detail was corrected later in the conversation, keep the
  corrected version and discard the original.

==================================================
EXTRACTION RULES
==================================================

- Record only information explicitly stated by the user.
- Do not infer facts about the user.
- Do not record assistant assumptions, opinions, or suggestions.
- Do not record the assistant's own wording, drafts, or generated
  documents. Record only the underlying facts the user supplied.
- Ignore fictional or roleplay details unless the user confirmed them as
  real.
- Ignore greetings, small talk, and other temporary conversational
  detail.
- Prefer information that will still matter many turns from now.
- If a section has no content, leave it empty rather than inventing one.

==================================================
OUTPUT
==================================================

Return ONLY the structured notes below. No preamble, no explanation, no
commentary.

TOPICS:
- What the conversation has covered so far.

USER_PREFERENCES:
- Stated preferences about how the user wants to be helped, including
  preferred language, tone, and format.

USER_GOALS:
- What the user is trying to achieve.

FACTS:
- Every concrete detail the user provided, copied verbatim. Group
  related details on one line where it aids readability, but never at
  the cost of dropping a value.

OPEN_ITEMS:
- Information the assistant asked for but has not received.
- Questions the user asked that were not fully answered.
- Anything explicitly deferred to later.

Conversation:

{conversation}
