## Fixed decisions
- Order: catalog→Postgres FIRST, then identity/output plumbing, then goal 1 (command tools), then goal 2 (catalog knowledge), then permission modes.
- Scan/build table reaches user verbatim: tool hands rendered MD to ChatService (option B, framework-free collector keyed by assistant_message_id); model gets a summary line only. Not LangGraph stream_writer (lock-in).
- Identity (user_id, is_admin) → run config `configurable`, set by ChatService. Never tool args.
- Tools bound once at startup (graph.py:114) → every user sees every tool; admin check INSIDE each tool. Per-user tool menus deferred.
- Confirmation baseline = plugin_prompt.txt rule ("state what you'll do, wait for yes") for costly/writing tools. Later → Manual / Accept-edits / Auto modes enforced in code (user wants Claude-Code-like modes).
- Reads: raw SELECT allowed. Guard = DB permissions, not string checks (`WITH x AS (DELETE…) SELECT`, pg_sleep, pg_read_file bypass text filters). Writes: typed `update_catalog_item(item_id, changes)`, Pydantic-validated, one row, before→after diff. Never raw UPDATE (missing WHERE = whole table).

## Phase 4 — goal 2: catalog knowledge
**2026-09-19 built, not live-tested.** Supersedes the planning bullets below where they differ.
- Settings: `DB_AGENT_USER`=llm_agent, `DB_AGENT_PASSWORD` default `llm_agent_local_only` (user asked for a default; warns when in use; "" disables). os.getenv, not get_valid_string.
- Core `app/database/agent_role.py` `AgentRole`: **lazy** — role created on first `grant_select(relation)` (plugin initialize), not at startup → job-app server (recycling excluded) never gets the role. Uses main async pool for DDL. Refuses role==DB_USER or existing role w/ super/createrole/createdb/bypassrls. Never names SUPERUSER attr (RDS master can't). ALTER ROLE password every start; role defaults read_only + statement_timeout. Own pool min1/max2, open timeout 10s; failure → disabled (logged), plugin still loads. `query(sql, max_rows)`: wrap `SELECT * FROM (\n{sql}\n) AS agent_query LIMIT n+1`, READ ONLY txn, SET LOCAL statement_timeout 5000, prepare=True, no params. `AgentQueryResult.as_text(max_chars)`. Probed on real PG (postgres db, RO txn): `%` ok, trailing `;`/`--` ok; `SELECT 1); SELECT 2` syntax err; data-modifying WITH refused in subquery; SET syntax err; timeout cancels; set_config(transaction_read_only) refused. Note: psycopg async needs SelectorEventLoop on Windows for ad-hoc scripts (app handles its own).
- ToolContext.agent_role. Application: AgentRole built in __init__, close registered after main pool (closes first).
- Plugin schema.py: view `recycling_catalog` WITH (security_barrier) WHERE tenant='default' (drop+create each start) — agent granted VIEW only; best-effort `CREATE EXTENSION pg_trgm`; `grant_agent_read(agent_role)` after ensure_schema. OPEN: per-tenant agent SQL (view per tenant / RLS) before 2nd tenant.
- Repo: get/insert (position=max+1)/update (updated_at=NOW())/delete, each logged INFO + CatalogStorageError.
- `catalog_tools.py`: recycle_query_catalog (rows→model, 200 rows/20k chars), recycle_create_catalog_item(canonical_label, copy_from_id?, values{}), recycle_update_catalog_item(item_id, changes{}), recycle_delete_catalog_item(item_id). All admin. Writes typed; validated via CatalogItem; alias clash via Catalog([...]) rebuild; change → reply block (update=before/after changed fields; create/delete=whole row). copy excludes id/aliases/observations. - **Gotcha found by test:** LangChain 1.6 `_parse_input` includes every top-level field with a default → omitted ≡ null. Fix: nested `changes`/`values` model, read `model_fields_set` (`_provided`).
- Token cost (measured via convert_to_openai_tool): create≈1040, update≈740, query≈310, all recycling≈2700/request. Loader estimate undercounts ($defs).
- plugin_prompt.txt: CATALOG ANALYSIS AND EDITING block (aggregate at scale, anomaly checklist, propose-don't-apply, one row per call).
- Planning bullets (2026-09-18):
- `query_catalog(sql)`: admin-only; READ ONLY txn; statement_timeout ~5s; row cap ~200; schema in tool description.
- Agent role (user design, 2026-09-18): CORE `app/database/agent_role.py` creates LOGIN role at startup (admin sync conn, like init_db) — CONNECT + schema USAGE, zero table grants. Env `DB_AGENT_USER`/`DB_AGENT_PASSWORD` (README + deploy/README). Core gives a separate small pool/conn as that role. Plugin `database/schema.py` does `GRANT SELECT ON recycling_catalog_items TO <agent role>`.
- **Must be a separate LOGIN connection, NOT `SET ROLE` on the main pool**: main DB_USER=postgres (superuser locally) → model SQL `RESET ROLE` / `set_config('role',…)` escapes back to superuser. Grants are the real guard; read_only/statement_timeout are user-settable GUCs → defense in depth only. Single statement only (extended protocol; verify psycopg3 behaviour).
- Local DB_USER=postgres = superuser → can CREATE ROLE. Server DB user: check deploy/README before phase 4.
- `update_catalog_item(item_id, changes)`: repo gets per-row update; validation via ItemMetadata; diff returned; confirm rule in prompt.
